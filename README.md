# RingerGuard

RingerGuard 是一个轻量级 Android 工具，用于防止手机被误切换到静音、震动或勿扰导致漏接来电。

项目目标：

> 让**运营商来电尽量自动恢复响铃**，同时把后台耗电压到接近 0。

当前版本：**V2.1.0**

---

## V2.1.0 更新：通讯录来电自动响铃 + 界面精简

V2.0.0 的「来电筛选」机制有一个 Android 系统层面的盲区：**系统默认只把「不在通讯录中的号码」交给来电筛选服务**，因此通讯录里的联系人来电不会触发恢复，可能仍然静音。V2.1.0 修复了这一点：

- **通讯录来电自动响铃**：申请 `READ_CONTACTS` 权限。Android 规定，来电筛选应用持有该权限后，系统才会把通讯录联系人来电也交给本应用处理。本应用**仅凭此权限让系统放行通讯录来电，不读取、不遍历、不上传任何联系人数据**。
- **界面精简**：移除内置诊断日志及相关按钮；权限改为「首次开启时按需引导、授予后自动隐藏」，常态界面只保留「开启/停止」「立即修复」「系统设置」。
- **代码清理**：删除诊断日志模块与死代码、合并冗余逻辑。

> 通讯录来电自动响铃同样**几乎不增加耗电**：`READ_CONTACTS` 只是改变系统的来电筛选策略，通讯录来电与陌生号码走完全相同的「来电瞬间唤起、跑完即结束」路径，不新增任何常驻进程或轮询。

---

## V2.0.0 重大重构：从「常驻保活」改为「来电触发」

旧版本（≤ V1.0.3）依赖一个**必须长期存活、时刻保持响应**的前台服务 + 4 小时 Handler 看门狗 + ContentObserver。在 OriginOS / iQOO 等系统上，进程被系统冻结后会出现典型的「**通知还在、服务还在，但功能全部失效**」（俗称假死），且看门狗本身也在被冻的进程里，根本跑不起来。

V2.0.0 换了思路：**平时什么都不跑，只在来电那一刻出手。**

- **运营商来电（自动恢复响铃）**：通过系统的「来电筛选」机制（`CallScreeningService` + `ROLE_CALL_SCREENING`）。在已授权且未被强行停止时，系统通常会在来电、**响铃之前**把本应用唤起一次，哪怕此前没有任何进程在运行。在那一刻退出静音/震动/勿扰、必要时恢复铃声音量，然后放行来电。
- **微信等网络电话（最佳努力）**：用系统 `JobScheduler` 每 4 小时低频触发一次恢复，「粗粒度地把手机大体保持在可响铃状态」。无法保证某一通 VoIP 来电一定有声音。

这样做的结果：

- **更省电**：待机时没有任何常驻进程；来电本就会唤醒设备，那次处理几乎不额外耗电。
- **不再假死**：两种触发都由系统按需唤起，**没有需要长期保活的进程，也就没有「会假死」的东西**。
- **更简单**：删除了前台服务、看门狗、ContentObserver 和常驻通知。

## 省电设计

RingerGuard 不使用高耗电保活方式。本项目**不使用**：

- 高频轮询
- WakeLock
- 常驻前台服务
- 分钟级后台自检

资源占用：

- 待机：无常驻进程，耗电接近 0
- 运营商来电：蹭「来电已唤醒设备」的时刻处理，几乎不额外耗电
- 低频兜底：`JobScheduler` 约每 4 小时一次，每次几毫秒，估算 < 0.1%/天

`JobScheduler` 任务两次运行之间**不保留进程**，由系统到点拉起新进程跑一次即结束，因此不会出现「假死」。

## iQOO / OriginOS 兼容

部分 iQOO / vivo / OriginOS 机型的「静音」并非标准响铃模式，而可能是：

1. 勿扰模式
2. 铃声流被 mute
3. 铃声音量被压到 0

RingerGuard 的恢复逻辑都做了处理：

1. 标准静音/震动：切回响铃模式。
2. 勿扰式静音：在具备勿扰权限时退出勿扰。
3. 铃声音量为 0：恢复到上一次记录的非 0 铃声音量（从未记录过则恢复到最大音量的一半）。
4. 铃声/通知流被 mute：尝试解除 mute。

不会修改媒体音量、闹钟音量。

## 权限说明

| 权限 | 用途 | 授予方式 |
| --- | --- | --- |
| `MODIFY_AUDIO_SETTINGS` | 调整响铃模式 / 铃声音量 | 普通权限，安装即授予，无弹窗 |
| **来电筛选角色**（`ROLE_CALL_SCREENING`） | **来电自动响铃的关键**：让系统在来电时唤起本应用 | 应用内点「授予来电筛选权限」，一次性授予 |
| **`READ_CONTACTS`** | **通讯录来电自动响铃的关键**：系统默认只把非通讯录号码交给来电筛选，授予后通讯录联系人来电才会同样恢复响铃 | 首次开启时弹窗授予，**仅持权限、不读取通讯录内容** |
| `ACCESS_NOTIFICATION_POLICY` | 退出勿扰式静音 | 仅在需要处理勿扰时，到系统设置里授予 |
| `RECEIVE_BOOT_COMPLETED` | 开机后重新登记低频兜底任务 | 普通权限 |

本版本**不再需要** `READ_PHONE_STATE`、`FOREGROUND_SERVICE`、`POST_NOTIFICATIONS`。

## 使用建议（iQOO / vivo / OriginOS）

1. 打开 RingerGuard，点「开启防静音/震动」。
2. 在随后弹出的引导里**依次授予「来电筛选权限」和「读取通讯录」**（这两项是来电自动响铃的关键；已授予的会自动跳过、不再询问）。
3. 如需处理勿扰式静音，点「打开勿扰权限设置」并允许。
4. 允许自启动、允许后台运行，并在最近任务中锁定本 App。
5. **不要手动「强行停止」本 App。**

## 已知限制

Android 和厂商系统不允许普通应用做到绝对永不被杀。以下情况下可能失效：

- 用户手动「强行停止」应用，或被厂商「深度睡眠 / 自动管理」打进强停状态——此时系统不会在来电时唤起本应用，需要重新打开一次。
- 未授予来电筛选权限——系统不会在来电时唤起本应用。
- 微信、QQ、WhatsApp 等**网络电话不走运营商电话栈**，无法被来电筛选捕获，只能靠每 4 小时低频兜底「尽量保持有声」，**可能偶尔没声音**。
- 来电筛选角色同一时间只能由一个应用持有；若与第三方拨号器 / 防骚扰应用冲突，需要二选一。

## 隐私说明

RingerGuard 不联网，不上传数据，不读取短信，不获取定位，不收集个人信息。

关于通讯录权限（`READ_CONTACTS`）：本应用申请该权限**仅用于满足 Android 的来电筛选策略**——系统只有在来电筛选应用持有此权限时，才会把通讯录联系人来电交给应用处理。本应用**不读取、不遍历、不存储、不上传任何联系人数据**，该权限只是让系统「放行」通讯录来电的开关。

来电筛选服务只在来电时执行「恢复响铃 + 放行来电」，**不读取、不记录任何号码或通话信息**。
