# RingerGuard

RingerGuard 是一个轻量级 Android 工具，用于防止手机被误切换到静音、震动或勿扰导致漏接来电。

项目目标很简单：

> 尽可能保持手机处于响铃可提醒状态，同时尽量减少后台耗电和系统打扰。

当前版本：**V1.0.2 稳定版**

---

## 主要功能

- 防止系统被切换到静音模式
- 防止系统被切换到震动模式
- 在具备勿扰权限时，自动退出勿扰模式
- 兼容部分 iQOO / vivo / OriginOS 机型中“看似响铃但实际铃声音量被压到 0”的情况
- 当铃声音量被压到 0 时，自动恢复到上一次记录的非 0 铃声音量
- 前台服务常驻运行，提高后台存活率
- 开机后、应用更新后自动恢复服务
- 最近任务被移除时进行一次被动恢复尝试
- 服务被系统恢复或重新启动时，会重新确认监听链路是否正常

---

## 省电设计

RingerGuard 不使用高耗电保活方式。

本项目不使用：

- 轮询
- WakeLock
- AlarmManager
- WorkManager
- 亮屏触发
- 解锁触发
- 高频后台自检

RingerGuard 主要依赖 Android 系统事件监听工作：

- 铃声模式变化
- 铃声音量变化
- 通知音量变化
- 勿扰模式变化
- 相关系统设置变化

只有在相关事件发生时才会执行恢复逻辑。

事件触发后，程序会进行一组短时间确认，用于兼容部分系统设置变化存在延迟或多阶段写入的情况。这不是长期轮询，也不会持续唤醒手机。

---

## V1.0.2 优化说明

V1.0.2 主要优化了后台稳定性和省电表现。

相比早期版本，本版本做了以下改进：

- 增强前台服务监听恢复逻辑
- 服务启动、系统恢复服务、再次启动服务时，会重新确认广播监听和设置监听是否注册
- 内存压力或低内存回调时，会尝试重挂监听
- 最近任务被移除时，会进行一次被动恢复尝试
- 收窄 Settings 监听范围，只监听铃声、通知音量、响铃模式、勿扰相关设置
- 过滤无关媒体音量变化，避免播放音乐、视频时误触发恢复逻辑
- 增加短时间节流，减少重复触发
- 避免重复保存相同铃声音量，减少无意义 SharedPreferences 写入
- 当前铃声音量已经等于目标音量时，不重复调用系统音量设置接口

这些优化主要用于降低以下情况发生的概率：

> 通知栏显示服务还在，但功能实际没有生效。

## 关于音量修改

RingerGuard 不会修改媒体音量、闹钟音量。

正常情况下，RingerGuard 也不会主动改变用户的铃声音量。

但为了兼容 iQOO / vivo / OriginOS 等部分机型的特殊静音机制，如果系统将铃声音量压到 0，RingerGuard 会尝试将铃声音量恢复到上一次记录的非 0 铃声音量。

也就是说：

- 不修改媒体音量
- 不修改闹钟音量
- 不主动改变正常铃声音量
- 仅在铃声音量被压到 0 时恢复铃声音量
- 通知流被系统 mute 时，会尝试解除 mute，但不会主动调整通知音量大小

## 权限说明

RingerGuard 可能需要以下权限才能正常工作：

### 通知权限

用于显示前台服务常驻通知。

前台服务通知是 Android 后台长期运行机制的一部分。如果关闭通知权限，服务稳定性可能下降。

### 勿扰权限

用于在系统进入勿扰模式时自动恢复。

如果不授予勿扰权限，RingerGuard 可能无法处理普通静音和震动模式。

### 开机自启动 / 后台运行权限

部分 iQOO / vivo / OriginOS 机型对后台服务限制较严格，建议手动允许：

- 自启动
- 后台运行
- 后台高耗电
- 通知权限
- 勿扰权限
- 最近任务锁定

不同系统版本名称可能不同，请以手机系统实际显示为准。

---

## 使用建议

在 iQOO / vivo / OriginOS 设备上，建议完成以下设置：

1. 授予通知权限
2. 授予勿扰权限
3. 允许自启动
4. 允许后台运行或后台高耗电
5. 在最近任务中锁定 RingerGuard
6. 不要手动强行停止应用

如果手动强行停止应用，Android 系统可能会禁止应用自动恢复。此时需要重新打开一次 RingerGuard。

---

## 工作原理

RingerGuard 通过前台服务运行，并监听系统响铃相关变化。

当检测到手机被切换到静音、震动、勿扰，或铃声音量被压到 0 时，会尝试恢复到响铃状态。

本项目不追求“强行保活”，而是尽量使用 Android 标准机制，在省电和稳定之间取得平衡。

核心设计原则：

> 不用高耗电方式强行保活，只在必要事件发生时进行恢复。

---

## 已知限制

Android 和厂商系统不允许普通应用做到绝对永不被杀。

在以下情况下，RingerGuard 可能失效：

- 用户手动强行停止应用
- 系统深度清理后台
- 厂商系统禁止自启动
- 厂商系统禁止后台运行
- 通知权限被关闭
- 勿扰权限未授予
- 系统极端省电模式限制后台服务

如果出现通知仍在但功能失效的情况，请尝试：

1. 打开 RingerGuard
2. 关闭后重新开启守护开关
3. 检查通知权限、勿扰权限、自启动、后台运行权限
4. 将应用加入系统后台白名单
5. 在最近任务中锁定应用

---

## 隐私说明

RingerGuard 不联网，不上传数据，不读取通讯录，不读取短信，不获取定位，不收集个人信息。

本项目只使用与响铃状态、防静音、防震动、防勿扰相关的系统能力。

---

## 版本状态

V1.0.2 是当前推荐稳定版本。

如果没有发现新的实际问题，后续不建议继续增加 WakeLock、轮询、AlarmManager、WorkManager 或其他高耗电保活方案。

本项目优先保持：

- 简单
- 省电
- 稳定
- 可控
- 不打扰用户
